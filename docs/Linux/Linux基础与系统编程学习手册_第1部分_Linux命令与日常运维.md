## 第 1 章 Linux 学习环境

### 1.1 Linux、内核和发行版

严格地说，**Linux 是操作系统内核**。Ubuntu、Debian、Red Hat Enterprise Linux、Rocky Linux 等把 Linux 内核、GNU 工具、软件包管理器和桌面或服务器组件组合起来，形成 Linux 发行版。因此，“Ubuntu 是 Linux 的一个版本”适合作为入门类比，但更准确的说法是“Ubuntu 是一个 Linux 发行版”。

不同发行版的目录结构和基础命令大体相通，但软件安装方式、默认配置、软件版本和管理工具可能不同。本手册示例使用 Ubuntu 虚拟机；工作中还可能遇到无图形界面的 Linux 服务器。

### 1.2 虚拟机、镜像与远程登录

VMware 是虚拟化软件，可以在 Windows 主机中创建或打开虚拟机。虚拟机拥有虚拟 CPU、内存、磁盘和网络设备，并在其中运行独立的操作系统；它不是 Linux 发行版，也不是 Shell。

本学习环境提供的是已经配置好的 Ubuntu 虚拟机目录，通常通过 VMware 的“打开虚拟机”功能载入其中的虚拟机配置文件，而不是把该目录当作 ISO 重新安装。首次打开复制来的虚拟机时，VMware 可能询问该虚拟机是“移动”还是“复制”而来；对他人提供的副本，应按镜像提供者的说明选择。界面大小异常时，可尝试切换全屏、等待客户机分辨率重新适配，并确认 VMware Tools 是否正常。

生产环境常通过 SSH 协议远程登录服务器。Xshell、PuTTY 等是终端客户端；**Shell** 则是服务器中解释命令的程序，两者不是同一概念。

### 1.3 终端与安全关机

在 Ubuntu 桌面环境中，可以从应用列表打开“终端”，也可在文件管理器的目录中使用“在终端中打开”。终端字号通常可用 `Ctrl+Shift++` 放大、`Ctrl+-` 缩小，具体快捷键随终端程序而异。

结束学习前，应先保存文件，再通过 Ubuntu 桌面的电源菜单正常关机。关机、重启命令参见[第五部分第 3 章命令速查表](Linux基础与系统编程学习手册_第5部分_综合练习与附录.md)中的 `reboot`、`poweroff`。

直接强制关闭虚拟机电源相当于突然断电，可能造成未写入数据丢失或文件系统损坏。挂起会保存当前运行状态，适合短暂停用，但不能替代长期保存和正常关机。

## 第 2 章 用户、提示符与 Shell

### 2.1 普通用户与 root

Linux 是多用户系统。普通用户通常只应修改自己拥有或获授权的文件；`root` 是超级用户，几乎可以修改系统中的任何内容。

Ubuntu 默认通常不鼓励直接使用 root 账户完成日常工作，而是让获授权的普通用户在必要时通过 `sudo` 临时取得管理员权限。输入密码时终端一般不显示星号或圆点，这是正常的。不要为了方便长期停留在高权限环境中；权限越高，误删除、误覆盖、误改用户和误改服务配置的影响越大。

典型 Bash 提示符可能类似：

```text
ubuntu@ubuntu:~$
root@ubuntu:/#
```

- 前一个 `ubuntu`：当前用户名。
- 后一个 `ubuntu`：主机名，不一定是发行版名称。
- `~`：当前用户的家目录缩写。
- `$`：通常表示普通用户提示符。
- `#`：通常表示 root 提示符。

提示符可以自定义，不能仅凭 `$` 或 `#` 做绝对的安全判断。

### 2.2 Shell 是什么

Shell 是命令语言解释器：读取输入、进行变量展开和重定向等处理，然后执行内建命令或启动外部程序。可以查看系统认可的登录 Shell：

```bash
cat /etc/shells
```

查看当前 Shell 的常用方式：

```bash
echo "$SHELL"     # 当前用户配置的登录 Shell
```

`$SHELL` 通常表示用户配置的登录 Shell，不一定能证明当前子进程中正在运行的解释器。

常见 Shell 包括：

- `sh`：传统 Bourne Shell 接口名；现代系统中的 `/bin/sh` 常是其他兼容 Shell 的链接，不一定指向 Bash。
- `bash`：Bourne Again Shell，由 GNU 项目开发，是许多 Linux 环境的常用 Shell。
- `dash`：小而快，Ubuntu 常用它提供 `/bin/sh`。
- `ksh`：KornShell。
- `csh`、`tcsh`：C Shell 及其扩展。
- `zsh`：功能丰富的交互式 Shell；现代 macOS 默认使用 zsh，而不是 Bash。

不同 Shell 有共同基础，但脚本并不保证可以不经修改地跨 Shell 运行。编写脚本时应明确解释器并遵循其语法。

### 2.3 Bash 补全、历史和编辑快捷键

输入命令、文件名或目录名的一部分后按 `Tab`，Bash 可尝试补全：

- 只有一个匹配项时，通常直接补全。
- 有多个匹配项时，继续输入可区分的字符；按两次 `Tab` 常可列出候选项。
- 补全还能减少长路径的拼写错误，并避免为了找文件反复 `cd`、`ls`。
- 参数补全通常由 `bash-completion` 提供，安装和启用方式随发行版与版本而异。启用前应先确认相应配置文件确实存在。

历史记录与行编辑：

| 功能 | 快捷键 | 说明 |
|---|---|---|
| 上一条/下一条历史 | `↑` / `↓`，或 `Ctrl+P` / `Ctrl+N` | 重用以前的命令 |
| 反向搜索历史 | `Ctrl+R` | 输入关键字增量搜索；再次按可找更早结果 |
| 光标左移/右移 | `Ctrl+B` / `Ctrl+F` | backward / forward |
| 行首/行尾 | `Ctrl+A` / `Ctrl+E` | Home / End |
| 删除光标后字符 | `Ctrl+D` | 空命令行时还可能表示结束输入/退出 Shell |
| 删除光标前字符 | `Backspace` | 常规退格 |

`history` 可列出历史命令。历史中可能包含路径、主机名或误输入的敏感信息，不应把密码直接写在命令行参数中。

### 2.4 命令、参数与帮助

最常见的命令行形式是：

```text
命令 [选项] [操作对象...]
```

命令、选项和参数通常以空白分隔。不同命令对参数的数量、顺序和含义有不同规定；不能把“所有参数都可任意换序”当成通则。

查看帮助：

```bash
man ls
ls --help
```

在 `man` 页面中可用方向键、Page Up/Page Down 或搜索功能浏览，按 `q` 退出。手册章节号用于区分同名主题。

```bash
man man        # 查看 man 自身手册
man 1 ls       # 查看第 1 节中的 ls 手册页
man -k ls      # 按关键字搜索与 ls 相关的手册页
man 2 read     # 查看系统调用手册页
man 3 printf   # 查看 C 库函数手册页
```

常见章节中，`1` 表示用户命令，`2` 表示系统调用，`3` 表示库函数。当命令名和函数名相同，例如 `printf`，应通过章节号区分。查错章节没有破坏性，换章节重查即可。

### 2.5 环境变量、PATH、env 与 echo

`env` 显示当前进程环境中的环境变量：

```bash
env
```

`PATH` 是由冒号分隔的一组目录。输入不带斜杠的外部命令名时，Shell 按 `PATH` 中的顺序寻找可执行文件：

```bash
echo "$PATH"
```

修改 `PATH` 时必须保留原值并使用冒号追加新目录。不要直接把它覆盖为单独一个路径，否则 `ls`、`cp` 等命令可能暂时无法按名称找到。持久化设置通常放在 `~/.bashrc`、`~/.profile` 等启动文件中，具体方式取决于登录方式和 Shell。

`echo` 可输出文本或展开后的变量值：

```bash
echo "hello world"
echo "$SHELL"
echo -n "no trailing newline"
echo "$?"       # 上一条前台命令的退出状态
```

按照惯例，退出状态 `0` 表示成功，非零表示某类失败，但具体数值含义由命令定义。带引号能更可靠地保留参数边界；“加引号就一定原样输出”并不严格，因为双引号内仍会发生变量展开等处理。

重定向由 Shell 处理，不是 `echo` 自己的“写文件功能”：

```bash
echo "first" > note.txt   # 覆盖目标文件
echo "second" >> note.txt # 追加到目标文件末尾
```

`echo` 并非“永远只能写一行”；它默认在输出末尾添加换行，也能输出多种内容。不过它不适合编辑长篇或结构复杂的文件。

## 第 3 章 Linux 目录与路径

### 3.1 单根目录树

Linux 没有 Windows 式的 `C:`、`D:` 盘符层级。所有可访问文件系统都组织在以 `/` 为根的单棵目录树下；其他磁盘或网络文件系统会挂载到树中的某个目录。

路径 `/home/ubuntu/project` 表示：从根目录 `/` 开始，依次进入 `home`、`ubuntu` 和 `project`。这里的 `/` 同时作为根目录名称和路径分隔符。

### 3.2 常见目录

不同发行版可能采用“merged `/usr`”布局，使 `/bin`、`/sbin`、`/lib` 成为指向 `/usr` 中对应目录的符号链接。下面按用途理解，不要机械依赖物理位置。

| 目录 | 主要用途 |
|---|---|
| `/` | 根目录，整个目录树的起点 |
| `/bin` | 启动和基本使用所需的用户命令；现代发行版中可能链接到 `/usr/bin` |
| `/sbin` | 系统管理相关命令；现代发行版中可能链接到 `/usr/sbin` |
| `/boot` | 内核、引导加载器和启动相关静态文件；GRUB 文件通常位于其子目录 |
| `/dev` | 设备文件 |
| `/etc` | 当前主机的系统级配置 |
| `/home` | 普通用户家目录的常用位置 |
| `/root` | root 用户的家目录，不能与根目录 `/` 混淆 |
| `/media` | 可移动媒体的常见自动挂载位置 |
| `/mnt` | 管理员临时挂载文件系统的常用位置 |
| `/opt` | 附加应用软件包 |
| `/proc` | 展示进程和内核信息的虚拟文件系统，不是普通磁盘目录 |
| `/sys` | 展示内核对象和设备信息的虚拟文件系统 |
| `/tmp` | 临时文件，清理策略由系统决定 |
| `/usr` | 可共享、通常只读的用户空间程序和数据层级 |
| `/usr/bin` | 大多数用户命令 |
| `/usr/sbin` | 非启动必需的系统管理命令 |
| `/usr/lib`、`/usr/lib64` | 程序库及相关数据，具体布局与架构有关 |
| `/usr/include` | C/C++ 等开发所用头文件 |
| `/usr/local` | 管理员在本机安装的软件层级 |
| `/usr/games` | 可选的游戏与教育程序目录 |
| `/srv` | 系统所提供服务的数据 |

`/selinux` 并不是所有系统都必须存在的通用根目录。SELinux 的接口和状态目录取决于发行版与挂载配置。

Linux 不依赖扩展名判定文件类型。普通文件可以没有扩展名，目录名也可以包含点号；`.d`、`.conf`、`.rc` 只是常见命名约定，不是内核强制的类型标记。

### 3.3 家目录、绝对路径和相对路径

普通用户的家目录通常是 `/home/用户名`，可用 `~` 表示：

```bash
cd /home/ubuntu
cd ~
cd              # cd 不带参数通常也回到家目录
```

- **绝对路径**从 `/` 开始，例如 `/etc/shells`。
- **相对路径**从当前工作目录开始，例如 `docs/notes.txt`。
- `.` 表示当前目录。
- `..` 表示父目录；根目录中的 `..` 仍解析为根目录。

常用路径书写规则：

| 写法 | 含义 |
| --- | --- |
| `./` | 当前目录，通常可省略 |
| `../` | 上一级目录 |
| `../../` | 向上两级，可叠加 |
| `folder/` | 进入子目录 |

示例：

```bash
cd /etc          # 绝对路径
cd ../var/log    # 相对路径
ls ./notes       # 显式从当前目录开始
```

### 3.4 cd：切换工作目录

**用途**：改变当前 Shell 的工作目录。`cd` 通常是 Shell 内建命令，因此 `which cd` 可能没有输出。

```bash
cd [目录]
```

常用示例：

```bash
cd /             # 根目录
cd ~             # 家目录
cd ..            # 父目录
cd ~/projects    # 家目录下的 projects
cd -             # 返回上一个工作目录
```

**易错点**：路径不存在、没有目录的执行（进入）权限，或路径中有空格却未正确引用，都会导致失败。

### 3.5 pwd：显示当前路径

**用途**：输出当前工作目录的完整路径，适合确认位置或供脚本判断环境。

```bash
pwd
```

提示符可能缩写路径或被自定义，所以脚本和严谨操作不应只靠肉眼看提示符。

### 3.6 which：查看命令路径

`which` 用于在 `PATH` 中查找可执行文件：

```bash
which ls
```

它主要按 `PATH` 查找外部程序，不一定能说明别名、函数和 Shell 内建命令；例如 `cd` 是内建命令，`which cd` 可能没有结果。

## 第 4 章 文件、目录、类型与权限

### 4.1 ls：列出目录内容

> **(重点)** `ls` 非常重要，重点掌握 `-R`、`-a`、`-l` 及其组合。

**用途**：列出文件或目录信息。

```bash
ls [选项] [文件或目录...]
```

常用选项：

- `-a`：包括名称以 `.` 开头的隐藏项，也会显示 `.` 和 `..`。
- `-A`：包括隐藏项，但不显示 `.` 和 `..`。
- `-l`：长格式，显示类型/权限、链接数、属主、属组、大小、时间和名称。
- `-R`：递归列出子目录。不要对庞大的目录树随意使用。
- `-h`：与 `-l` 配合，以更易读的单位显示大小。

选项可组合：

```bash
ls -al
ls -lah /etc
ls -R small-demo-directory
```

不提供操作对象时，`ls` 查看当前目录。文件颜色由终端和 `LS_COLORS` 等配置决定，不能作为判断文件类型的可靠依据。

#### 理解 `ls -l`

示意输出：

```text
-rw-r--r-- 1 ubuntu developers 128 Aug  2 10:30 note.txt
```

字段依次包括：

1. 文件类型与权限。
2. 硬链接数。
3. 属主。
4. 属组。
5. 文件大小（默认字节）。
6. 时间戳；通常是最后内容修改时间，不是可靠的“创建时间”。
7. 文件名。

第一个字符表示类型：

| 字符 | 类型 |
|---|---|
| `-` | 普通文件 |
| `d` | 目录 |
| `l` | 符号链接 |
| `b` | 块设备 |
| `c` | 字符设备 |
| `s` | Unix 域套接字 |
| `p` | 命名管道（FIFO） |

“所有目录总是 4096 字节”的说法不成立。许多 ext 文件系统上的小目录常见 4096 字节，但目录大小取决于文件系统和目录项数量，也不等于目录中所有文件的总大小；统计内容占用应使用 `du`。

### 4.2 权限、属主和属组

类型字符后的九位分为三组：

```text
rwx rwx rwx
│   │   └─ 其他用户（others）
│   └───── 属组（group）
└───────── 属主（user）
```

- `r`：读。对目录表示可列出名称，但通常还需 `x` 才能访问目录项。
- `w`：写。对目录表示可创建、删除或重命名目录项，实际还受 `x` 等条件影响。
- `x`：执行。对目录表示可进入/遍历。
- `-`：该位置没有相应权限。

数字表示法中 `r=4`、`w=2`、`x=1`，每组三位相加：

```text
rwx r-x r--  ->  7 5 4  ->  754
```

在 shell 命令中通常写 `754` 即可；在 C 语言源码等上下文中，前导 `0` 常用于表示八进制字面量。不要把“所有八进制都必须以 0 开头”套用到所有工具和上下文。

长列表中还可能出现 `s/S`（setuid 或 setgid）和 `t/T`（sticky bit）。现代 Linux 中 sticky bit 最常见于共享目录，例如 `/tmp`：在满足权限的同时，通常只有文件所有者、目录所有者或 root 可以删除/重命名其中的文件。“让可执行文件正文留在内存”属于历史语义，不适合解释现代 Linux 的常见行为。

### 4.3 touch：创建空文件或更新时间

**用途**：文件不存在时创建空文件；存在时更新访问时间和修改时间，默认不清空内容。

```bash
touch [选项] 文件...
```

```bash
touch note.txt
touch a.txt b.txt c.txt
```

**易错点**：`touch existing.txt` 不会把现有文件覆盖成空文件。若权限不足或父目录不可写，创建会失败。

### 4.4 mkdir：创建目录

**用途**：创建一个或多个目录。

```bash
mkdir [选项] 目录...
```

常用选项：

- `-p` / `--parents`：按需创建缺失的父目录，已存在时不因此报错。
- `-m MODE` / `--mode=MODE`：指定新目录模式，仍应理解 umask 和实现语义。
- `-v` / `--verbose`：显示创建过程。

```bash
mkdir demo
mkdir one two three
mkdir -p project/src/include
mkdir -m 750 private-dir
```

同一父目录中不能存在同名目录项；名称区分大小写。创建者还必须对父目录具有相应权限。

### 4.5 rmdir：删除空目录

**用途**：只删除空目录，适合在删除前确认目录确实为空。

```bash
rmdir [选项] 目录...
rmdir empty-dir
rmdir -p a/b/c
```

`-p` 会在每一级变空且允许删除时继续处理父目录。`rmdir` 的限制是一种保护，不应简单视为“没有用”。

### 4.6 rm：删除文件或目录

> **(重点)** 递归删除及 `-r`、`-f` 是重点，必须与安全检查一起掌握。

**用途**：删除目录项。命令行删除通常不进入回收站。

```bash
rm [选项] 文件...
```

常用选项：

- `-r` / `-R` / `--recursive`：递归删除目录及其内容。
- `-i`：每次删除前询问。
- `-I`：删除多个文件或递归删除前进行一次较温和的确认。
- `-f` / `--force`：忽略不存在文件，且通常不询问；它不是“删除目录”的选项。

```bash
rm note.txt
rm -i important.txt
rm -r old-demo
```

> **高风险命令：** 不要把 `rm -rf` 当作默认删除方式。执行递归删除前先用 `pwd` 和 `ls -- 目标` 核对路径；路径来自变量时先确认变量非空。不要在根目录、家目录或真实项目目录上做删除实验。

### 4.7 mv：移动或重命名

> **(重点)** 这是本批命令中最难分析的一个，重点是判断目标路径如何影响“移动”或“重命名”。

**用途**：移动或重命名文件、目录。

```bash
mv [选项] 源 目标
mv [选项] 源... 目标目录
```

```bash
mv old.txt new.txt       # 目标不是现有目录：改名或移动到指定路径
mv report.txt archive/   # 目标是现有目录：移入该目录
mv a.txt b.txt archive/  # 多个源必须给出目标目录
```

目标是现有目录时，默认把源放入该目录并保留源的基本名称；否则第二个操作数是目标路径。不能仅用“目标是否存在”或“文件与目录是否同类型”推断全部结果：现有目标、非空目录、权限、符号链接、跨文件系统移动和选项都会影响行为。

常用安全选项：

- `-i`：覆盖前询问。
- `-n`：不覆盖现有目标。
- `-b`：覆盖前备份目标。
- `-v`：显示处理过程。
- `-T`：把目标明确当作普通目标，而不是目标目录；初学阶段应先阅读手册再用。

同一文件系统内通常通过重命名完成；跨文件系统时实现通常需要复制成功后再删除源。因此大批量跨盘移动时要核对空间和结果。

### 4.8 cp：复制文件或目录

**用途**：复制后保留源对象。

```bash
cp [选项] 源 目标
cp [选项] 源... 目标目录
```

```bash
cp note.txt note.bak
cp note.txt backup/
cp -R project backup/
```

常用选项：

- `-R` / `-r`：递归复制目录；GNU 工具中更推荐语义明确的 `-R`。
- `-i`：覆盖前询问。
- `-n`：GNU 传统的不覆盖选项，但其跨平台退出状态存在差异；自动化时应阅读本机手册。
- `-a`：归档复制，递归并尽量保留属性和链接关系。
- `-p`：保留指定属性。
- `-v`：显示处理过程。

复制到现有目录时，源会成为该目录下的一个项目；复制到不存在的目标路径时，会以目标名称创建副本。目录是否合并、同名项目是否覆盖以及符号链接如何处理取决于目标状态和选项，重要数据应先使用 `-i`、备份或测试目录验证。

### 4.9 whoami：查看当前用户名

**用途**：输出当前有效用户的用户名，适合在脚本、远程终端或多个用户来回切换后确认当前身份。

```bash
whoami
```

它只显示用户名，不显示用户组、登录终端或权限细节。终端提示符里也可能显示用户名，但提示符可以自定义；需要脚本判断时应使用命令输出。

### 4.10 chmod：修改访问权限

> **(重点)** 从 `ls -l` 的权限字段接入，掌握用数字权限修改文件或目录权限。

**用途**：修改文件或目录的访问权限。

```bash
chmod [权限] 文件或目录...
```

数字权限仍按 `r=4`、`w=2`、`x=1` 相加。例如：

```bash
chmod 766 demo.cpp
chmod 755 script.sh
chmod -R 755 project
```

也可以使用符号方式：

```bash
chmod u+x run.sh      # 给属主增加执行权限
chmod go-w note.txt   # 去掉属组和其他用户的写权限
chmod a+r file.txt    # 所有人增加读权限
```

**易错点**：

- `chmod 766 demo.cpp` 中权限值在前、文件名在后，顺序不能随意颠倒。
- 文件拥有 `x` 权限只表示内核允许尝试执行；源代码文件、文本文件若没有正确解释器或不是可执行格式，仍可能执行失败。
- 文件颜色可能因可执行权限变绿，但颜色由终端配置决定，不能作为可靠判断依据。
- `chmod -R` 会递归影响整棵目录树，真实项目中使用前必须先核对路径。

### 4.11 chown 与 chgrp：修改属主和属组

**用途**：`chown` 修改文件或目录的属主，也可同时修改属组；`chgrp` 只修改属组。

```bash
chown [属主][:属组] 文件或目录...
chgrp 属组 文件或目录...
```

常见示例：

```bash
sudo chown root:root aa
sudo chown ubuntu:developers report.txt
sudo chgrp developers report.txt
```

把文件改成其他用户尤其是 root 名下，通常需要管理员权限。普通用户不能随意把自己的文件“送给”高权限用户，因为这会改变文件的管理边界。`chgrp` 只修改属组；入门阶段可优先掌握 `chown 用户:组 文件` 这种同时指定属主和属组的写法。

### 4.12 sudo：临时以管理员权限执行命令

**用途**：让获授权的普通用户临时以 root 权限执行后面的单条命令。

```bash
sudo 命令 [参数...]
```

示例：

```bash
sudo chown root:root aa
sudo chmod 777 aa
sudo apt-get install tree
```

`sudo` 不是单独“变强”的开关，它只影响后面那条命令。第一次使用时通常要求输入当前用户自己的密码；通过后会在短时间内缓存认证结果。不要养成“Permission denied 就无脑加 sudo”的习惯，先确认目标路径、命令作用和自己是否确实有授权。

### 4.13 umask：默认权限掩码

> **(重点)** `umask` 不是简单减法，而是从默认权限中拿走对应权限位。

**用途**：查看或设置当前 Shell 及其子进程创建新文件、目录时使用的权限掩码。

```bash
umask
umask 002
```

常见默认基准：

- 普通文件创建时通常以 `666` 为基准，因为新文本文件默认不应带执行权限。
- 目录创建时通常以 `777` 为基准，因为进入目录需要 `x` 权限。

实际权限可理解为“默认权限中去掉 `umask` 指定的权限位”。例如 `umask 002` 会拿走其他用户的写权限，所以普通文件常见为 `664`，目录常见为 `775`。

不要把 `umask` 当作十进制减法。若原权限位本来就没有某项权限，掩码想拿也拿不走；例如从 `753` 中按 `222` 拿走写权限，结果是 `551`，不是简单相减得到的数。

## 第 5 章 查看内容、统计与存储空间

### 5.1 cat：输出或连接文件

**用途**：把一个或多个文件内容写到标准输出，适合较短文本。

```bash
cat [选项] [文件...]
cat /etc/shells
cat part1.txt part2.txt
```

不提供文件时，`cat` 从标准输入读取并写到标准输出；终端中可按 `Ctrl+D` 发送输入结束标志。`cat` 会持续读取，不是每遇到一个换行就结束整个命令。

大文件不宜直接 `cat` 到终端，可改用 `less`、`head` 或 `tail`。

### 5.2 more 与 less：分页查看

```bash
more file.txt
less file.txt
```

- `more`：分页向前浏览，部分实现也支持有限的回退。
- `less`：通常可自由向前、向后滚动和搜索，更适合大文件。
- 常见操作：空格下一页，`b` 上一页，`/关键词` 搜索，`n` 下一个匹配，`q` 退出；以本机帮助为准。

`more` 退出后是否把已显示内容留在终端上与程序和终端设置有关，不应作为二者的核心区别。

### 5.3 head 与 tail：查看开头或结尾

```bash
head [选项] [文件...]
tail [选项] [文件...]
```

默认各显示 10 行：

```bash
head -n 5 file.txt
tail -n 5 file.txt
tail -f app.log
```

`tail -f` 可持续跟踪日志追加内容，按 `Ctrl+C` 结束。`head -5`、`tail -5` 在 GNU 工具中常可使用，但 `-n 5` 更清晰、可移植。

### 5.4 clear：清理当前终端显示

```bash
clear
```

`clear` 让终端呈现干净视图，但通常不会删除命令历史、文件内容或所有终端滚动缓冲。不要把它当作隐私清除工具。

许多终端还支持 `Ctrl+L` 触发类似清屏的行编辑功能，使用 `Shift+PageUp`、`Shift+PageDown` 浏览终端滚动缓冲；具体行为由终端模拟器和快捷键配置决定。

### 5.5 tree：树形显示目录

```bash
tree [目录]
tree -L 2 project
```

`tree` 以层级结构展示目录。它不一定默认安装；需要时可通过当前发行版的官方软件源安装，例如 Ubuntu 系可使用 `sudo apt-get install tree`。

在大型目录树或根目录运行会产生大量输出，应使用具体目录或 `-L` 限制深度。

### 5.6 wc：统计换行、词、字符和字节

> **(重点)** 重点掌握 `-c`、`-l`、`-w`；本手册同时纠正其统计含义。

```bash
wc [选项] [文件...]
```

常用选项：

- `-l` / `--lines`：统计换行符数量。文件最后一行没有换行符时，该尾部片段可能不计入。
- `-w` / `--words`：统计由空白分隔的非空序列，不是自然语言意义上的“中文词数”。
- `-c` / `--bytes`：统计字节数。
- `-m` / `--chars`：按当前区域设置统计字符数；多字节编码下可能与 `-c` 不同。
- `-L`：显示最长行的显示宽度。

```bash
wc notes.txt
wc -l notes.txt
wc -c notes.txt
wc -m notes.txt
```

`wc -l` 统计换行数，`-c`/`--bytes` 统计字节，`-m`/`--chars` 统计字符，三者不能混用。

### 5.7 od：按指定格式查看底层数据

**用途**：以八进制、十六进制、字符等表示查看文件字节，适合分析不可见字符或二进制数据。

```bash
od [选项] [文件...]
od -tcx1 file.bin
```

`-t TYPE` 指定格式，常见类型包括：

- `c`：字符或反斜杠转义序列。
- `d[SIZE]`：有符号十进制整数。
- `f[SIZE]`：浮点数。
- `o[SIZE]`：八进制整数。
- `u[SIZE]`：无符号十进制整数。
- `x[SIZE]`：十六进制整数。

`SIZE` 及组合格式的合法值取决于实现，应查看 `man od`。它不是“没用的命令”，在编码、协议、文件格式和控制字符排查中很实用。

### 5.8 du：估算文件和目录占用

**用途**：递归估算目录树中各文件所占磁盘空间。

```bash
du [选项] [文件或目录...]
```

```bash
du -h project
du -sh project
du -B 1M project
```

- `-h`：使用易读单位。
- `-s`：只给出每个参数的汇总。
- `-B SIZE`：指定输出块大小；`-m`、`-k`、`-b` 是相关实现提供的便捷形式。

`ls -l` 显示目录项本身的元数据大小，不会递归统计目录内容，因此不能替代 `du`。稀疏文件、硬链接、文件系统压缩和权限都可能使 `du` 与文件表面长度不同。

### 5.9 df：查看文件系统空间

> **(重点)** `df -h` 在实际工作中经常用于检查服务器磁盘空间。

**用途**：报告已挂载文件系统的总量、已用、可用空间和挂载点。

```bash
df [选项] [文件...]
df -h
df -h /home
```

- `-h`：用 KiB、MiB、GiB 等易读单位显示。
- `--block-size=MB`、`--block-size=GB`：按指定单位显示；具体单位语义以 GNU Coreutils 手册为准。

`du` 回答“某个目录树占用了多少空间”，`df` 回答“某个文件系统还有多少空间”。文件已被删除但仍被进程打开、保留块、文件系统元数据等情况，都可能让二者数值不同。

## 第 6 章 查找、检索与软件安装

### 6.1 find：按文件名查找

**用途**：在指定路径下递归查找文件或目录。

```bash
find [路径...] [表达式]
find . -name "*.c"
find ./project -name "main*"
```

`find .` 和 `find ./` 都表示从当前目录开始。`-name` 按名称匹配，通配符要加引号，避免先被 Shell 展开：

- `"a*"`：以 `a` 开头。
- `"*a"`：以 `a` 结尾。
- `"*a*"`：名称中包含 `a`。

不要轻易从 `/` 根目录开始查找，范围太大、速度慢，还可能遇到大量权限错误。先选准项目目录或家目录，必要时再扩大范围。

### 6.2 grep：按内容检索

> **(重点)** 记住 `-i`、`-n`、`-R` 这几个常用选项。

**用途**：在文本文件中查找匹配的字符串或正则表达式。

```bash
grep [选项] 模式 [文件或目录...]
```

常用选项：

- `-i`：忽略大小写。
- `-n`：显示匹配行号。
- `-R` / `-r`：递归搜索目录。

示例：

```bash
grep "return" main.cpp
grep -n "return" main.cpp
grep -R "TODO" .
grep -Rni "error" logs/
```

`grep` 面向文本内容。压缩包、图片、可执行文件等二进制文件即使能被扫描，也不适合按普通文本理解。注意 `grep` 不是在文件名里找，而是在文件内容里找。

### 6.3 apt-get、dpkg 与源码安装

**用途**：安装、删除和更新软件。Ubuntu 系常见三类来源：软件源包、本地 `.deb` 包和源码。

软件源安装常用：

```bash
sudo apt-get update
sudo apt-get install tree
sudo apt-get remove tree
```

- `update`：更新本机的软件包索引，不等于把所有软件升级到最新版。
- `install`：从软件源下载并安装指定软件包。
- `remove`：删除软件包，配置文件是否保留取决于具体命令和选项。

本地 `.deb` 包常用：

```bash
sudo dpkg -i package.deb
sudo dpkg -r package-name
```

`dpkg -i` 后面接 `.deb` 文件路径；`dpkg -r` 后面通常接已安装的软件包名，不一定等于文件名。

源码安装一般是“取得源码、编译、安装”的流程。此处只介绍概念和 `make`，暂不把具体项目的编译参数固定成通用模板。真实工作中应优先阅读项目的 `README`、`INSTALL` 或官方文档。

## 第 7 章 文件系统挂载与压缩包

### 7.1 文件系统与挂载点

文件系统是设备上组织文件和目录的数据结构。硬盘、U 盘、镜像文件等要存放文件，通常需要先有文件系统。常见类型包括 Linux 常用的 ext 系列、Windows 常见的 FAT32/exFAT/NTFS，以及光盘镜像常见的 ISO 9660。

Linux 把设备挂载到单根目录树中的某个目录，这个目录叫挂载点。挂载成功后，访问挂载点就相当于访问设备里的文件。挂载会遮住挂载点原来显示的内容；卸载后，原来的目录内容才会重新显现。

### 7.2 mount 与 umount：挂载和卸载

**用途**：`mount` 将设备或文件系统挂到目录树中；`umount` 卸载挂载点。

```bash
sudo fdisk -l
sudo mount /dev/sdb1 /mnt
sudo umount /mnt
```

基本流程：

1. 用 `sudo fdisk -l` 或其他工具确认设备名。
2. 准备一个空目录作为挂载点，例如 `/mnt/usb`。
3. 使用 `sudo mount 设备名 挂载点` 挂载。
4. 使用完后先退出挂载点目录，再 `sudo umount 挂载点`。

`mount` 的通用形式为 `mount [-t vfstype] -o options device dir`。多数常见设备能自动识别文件系统类型；特殊设备、镜像文件或网络文件系统才需要显式 `-t`、`-o`。不要随手把正在使用的系统分区反复挂载到练习目录中练习；真实 U 盘卸载前也要确认没有程序正在读写。

### 7.3 tar、zip 与 rar：压缩包管理

**用途**：打包、压缩和解压文件。Linux 中 `tar` 最常见，`zip`、`rar` 更多用于兼容 Windows 生态。

#### tar：打包与压缩

单个参数含义：

- `c`：create，创建归档（压缩方向）。
- `x`：extract，从归档中释放文件（解压方向）。
- `t`：list，只列出归档内容，不解压。
- `v`：verbose，显示详细过程，可省略。
- `f`：file，后面紧跟归档文件名；通常放在参数组末尾。
- `z`：通过 gzip 处理，对应 `.tar.gz` / `.tgz`。
- `j`：通过 bzip2 处理，对应 `.tar.bz2`。
- `J`：通过 xz 处理，对应 `.tar.xz`。
- `-C 目录`：解压到指定目录（仅解压时可用）。

组合逻辑：`c` 或 `x` 决定方向，`z`/`j`/`J` 决定压缩算法，`v` 可选，`f` 负责指定文件名。新版 GNU tar 能根据文件内容自动识别压缩格式，省略 `z`/`j`/`J` 通常也能工作，但显式写出更清晰。

**压缩（打包）**：

```bash
tar cvf dir.tar dir              # 只打包，不压缩
tar zcvf dir.tar.gz dir          # 打包并用 gzip 压缩
tar jcvf dir.tar.bz2 dir         # 打包并用 bzip2 压缩
tar Jcvf dir.tar.xz dir          # 打包并用 xz 压缩
```

**解压缩**：

```bash
tar xvf dir.tar                  # 解包到当前目录
tar zxvf dir.tar.gz              # 解包并解压 gzip
tar jxvf dir.tar.bz2             # 解包并解压 bzip2
tar Jxvf dir.tar.xz              # 解包并解压 xz
tar zxvf dir.tar.gz -C ~/test    # 解压到指定目录
```

**查看内容（不解压）**：

```bash
tar tvf dir.tar                  # 列出归档中的文件
tar tzvf dir.tar.gz              # 列出压缩包内容
```

#### zip / unzip

```bash
zip -r dir.zip dir               # 压缩：-r 递归包含目录内容
unzip dir.zip                    # 解压到当前目录
```

#### rar / unrar

```bash
rar a -r newdir.rar dir          # 压缩：a 表示添加文件到归档
unrar x newdir.rar               # 解压并保留目录结构
```

压缩后文件不一定总比原目录小，尤其是很小的文件或已经压缩过的数据。“多个文件先放入一个目录再压缩”的做法适合初学者统一管理；实际上部分工具支持一次指定多个文件，但先整理成目录更不容易漏文件。

<a id="chapter-8"></a>
## 第 8 章 进程、作业与信号

### 8.1 who：查看当前在线用户

**用途**：显示当前登录系统的用户、登录终端、登录时间等信息。

```bash
who
who -H
```

`whoami` 只回答“当前有效用户名是谁”；`who` 更偏向“有哪些会话正在登录”。`-H` 可显示表头，方便理解列含义。

### 8.2 ps：查看进程

> **(重点)** `ps` 在后续服务器部署和排查中会经常使用。

**用途**：显示当前系统中的进程信息。

```bash
ps
ps aux
```

`ps aux` 常见字段：

| 字段 | 含义 |
|---|---|
| `USER` | 进程所属用户 |
| `PID` | 进程 ID |
| `%CPU` | CPU 使用比例 |
| `%MEM` | 内存使用比例 |
| `VSZ` | 虚拟内存大小 |
| `RSS` | 常驻物理内存大小 |
| `TTY` | 控制终端，`?` 常表示没有控制终端 |
| `STAT` | 进程状态 |
| `START` | 进程启动时间 |
| `TIME` | 累计使用 CPU 时间 |
| `COMMAND` | 启动进程的命令 |

常见状态：

- `R`：运行或可运行。
- `S`：可中断睡眠。
- `D`：不可中断睡眠，常与 I/O 等等待有关。
- `T`：停止或被跟踪。
- `Z`：僵尸进程。

状态后还可能组合 `<`、`N`、`l`、`s`、`+` 等附加标志。初学阶段先重点看 `PID`、`STAT` 和 `COMMAND`，再结合 CPU、内存列判断程序是否还在运行。

### 8.3 jobs、fg 与 bg：作业控制

**用途**：管理当前 Shell 里启动、暂停或放到后台的作业。

```bash
jobs
fg %1
bg %1
```

不带文件名的 `cat` 会持续等待标准输入，进程不会结束。常见快捷键：

- `Ctrl+Z`：暂停当前前台作业，并把它放入作业列表。
- `fg %作业号`：把作业调回前台。
- `bg %作业号`：让暂停的作业在后台继续运行。
- `Ctrl+C`：向前台进程发送中断，常用于结束当前命令。

`jobs` 只显示当前 Shell 管理的作业，不等于全系统进程列表；全系统进程仍用 `ps` 查看。

### 8.4 kill：向进程发送信号

**用途**：向指定 PID 发送信号。它不只用于“杀死进程”，只是终止进程是最常见用途。

```bash
kill -l
kill PID
kill -15 PID
kill -9 PID
```

- `kill -l`：列出可用信号。
- `15` / `SIGTERM`：请求进程正常终止，默认信号通常就是它。
- `9` / `SIGKILL`：由内核强制终止，进程无法捕获或清理。

优先尝试 `kill PID` 或 `kill -15 PID`；只有进程无法响应、已经挂起或必须强制结束时，再考虑 `kill -9 PID`。强制终止可能导致临时文件、锁文件、事务或数据写入没有正常收尾。

<a id="chapter-9"></a>
## 第 9 章 用户管理

### 9.1 useradd、passwd 与 su

**用途**：创建用户、设置密码、切换用户。用户管理通常需要管理员权限。

```bash
sudo useradd -s /bin/bash -m -d /home/zhangsan zhangsan
sudo passwd zhangsan
su zhangsan
sudo su
```

常见选项：

- `useradd -s /bin/bash`：指定登录 Shell。
- `-m`：家目录不存在时创建。
- `-d /home/用户名`：指定家目录。
- `-g 组名`：指定主组；组必须已存在。初学阶段不指定时，系统通常会按发行版规则处理默认组。

`passwd 用户名` 用于设置或修改密码。普通用户通常只能改自己的密码；管理员可改其他用户密码。`su 用户名` 切换到目标用户，通常要输入目标用户密码；`sudo su` 是先用自己的 sudo 权限提权，再进入 root Shell，风险更高，不适合作为日常习惯。

### 9.2 userdel：删除用户

**用途**：删除系统用户。

```bash
sudo userdel 用户名
sudo userdel -r 用户名
```

`-r` 会连同用户家目录和邮件池等相关文件一起删除，属于破坏性操作。删除前应确认：

- 当前没有登录到要删除的用户。
- 该用户没有仍在运行的重要进程。
- 家目录中没有需要保留的数据。

删除用户失败通常是因为该用户仍被某个 Shell 进程占用；应先退出相关会话或结束对应进程，再重新删除。

<a id="chapter-10"></a>
## 第 10 章 网络排查

### 10.1 ifconfig：查看或配置网卡

**用途**：查看网卡地址、状态和收发统计，也可启用或关闭网卡。

```bash
ifconfig
sudo ifconfig ens33 down
sudo ifconfig ens33 up
sudo ifconfig ens33 192.168.1.100
```

输出中常见信息包括网卡名、MAC 地址、IPv4/IPv6 地址、广播地址、掩码、MTU、收发包数量等。`lo` 是本地回环接口，常见地址是 `127.0.0.1`；它通了只说明本机协议栈可用，不代表外部网络一定通。

现代 Linux 也常使用 `ip addr`、`ip link` 等 `iproute2` 命令；本节保留 `ifconfig`，同时补充现代 `iproute2` 工具。

### 10.2 ping：测试连通性

**用途**：向主机发送 ICMP 回显请求，用于判断网络层是否可达，并观察延迟。

```bash
ping 192.168.1.1
ping www.baidu.com
```

能收到回复通常说明基础网络连通；请求超时可能是地址写错、双方不在同一网络、防火墙丢弃 ICMP、目标关机或路由不可达。写网络程序时，先用 `ping` 判断设备是否能互通，再排查应用层代码，会省掉很多绕路。

输出中的 `time` 是往返延迟，`ttl` 是数据包生存时间相关字段。延迟会波动，偶尔变大不一定就是程序错误。

### 10.3 netstat、nslookup 与 finger

`netstat` 可查看网络连接、路由、端口和协议状态：

```bash
netstat
netstat -an
```

它能帮助区分 TCP/UDP、本地地址与端口、远端地址与端口、连接状态等。现代系统中也常用 `ss` 替代 `netstat`，但仍应掌握 `netstat` 的基本读法。

`nslookup` 用于查询域名解析结果：

```bash
nslookup www.baidu.com
```

一个域名可能返回多个 IPv4 或 IPv6 地址，这是负载均衡、就近调度或多服务器部署的常见现象。`ping` 到的地址可能只是其中之一。

`finger` 可查看用户信息：

```bash
finger 用户名
```

它在许多现代系统中默认未安装或被禁用，了解即可；不要把它作为必须依赖的排障工具。

<a id="chapter-11"></a>
## 第 11 章 其他常用命令与工作习惯

### 11.1 alias：命令别名

**用途**：给较长或常用的命令组合起短名字。

```bash
alias
alias ll='ls -alF'
alias rm='rm -i'
```

直接在终端里设置的别名只影响当前 Shell；常用别名通常写在 `~/.bashrc` 等配置文件中。别名会改变输入命令后的实际执行内容，所以排查时要意识到 `ll` 可能不是独立程序，而是 `ls -alF` 的别名。

### 11.2 date、reboot、poweroff 与 free

`date` 显示或设置系统日期时间：

```bash
date
```

普通查看不需要管理员权限；设置系统时间通常需要权限，并可能影响日志、构建系统和证书校验。

`reboot` 重启系统，`poweroff` 关闭系统：

```bash
sudo reboot
sudo poweroff
```

公司里的 Linux 服务器通常在远端，不能像本地电脑一样随手关机。远程服务器关机后可能无法自行开机，必须联系机房或云平台处理；真实环境中执行前要确认维护窗口、登录方式和业务影响。

`free -m` 查看内存使用情况：

```bash
free -m
```

这里的 `free` 表示“空闲”，不是“免费”。常见列包括总量、已用、空闲、缓存和可用内存。Linux 会积极利用空闲内存做缓存，因此不能只看 `free` 一列就判断内存不够。

### 11.3 SSH、NFS 与 FTP 服务搭建（补充）

服务器搭建不能只记一组命令。应始终按“安装—配置—校验—启动—放行网络—客户端验证—查看日志”的顺序操作，并先在隔离虚拟机或实验网段练习。发行版、软件版本和网络策略不同，包名、配置项及服务名可能变化；执行前先阅读本机的 `man`、示例配置和发行版文档。

#### 11.3.1 SSH：远程登录与文件传输（补充）

Ubuntu/Debian 常用 OpenSSH 服务端：

```bash
sudo apt update
sudo apt install openssh-server
sudo sshd -t
sudo systemctl enable --now ssh
systemctl status ssh --no-pager
ss -lntp | grep ':22'
```

`sshd -t` 在重载前检查配置语法；若它报错，不要重启服务。客户端可先在同机或实验网中验证：

```bash
ssh 用户名@服务器IP
sftp 用户名@服务器IP
scp ./local.txt 用户名@服务器IP:/home/用户名/
```

生产环境应优先使用密钥认证，确认密钥登录可用后再考虑禁用密码登录；修改端口不能替代认证、防火墙和更新维护。远程修改 `/etc/ssh/sshd_config` 时应保留一个已登录会话，先执行 `sudo sshd -t`，再使用 `sudo systemctl reload ssh`，并从第二个终端验证新连接，避免把自己锁在服务器外。不要直接允许 root 密码远程登录，也不要在文档中保存真实密码或私钥。

排查顺序：

```bash
ip addr
ping -c 3 服务器IP
ss -lntp | grep ':22'
systemctl status ssh --no-pager
journalctl -u ssh --since today
ssh -v 用户名@服务器IP
```

#### 11.3.2 NFS：在受信网络共享目录（补充）

NFS 适合 Unix/Linux 主机间共享目录，不应直接暴露到不受信网络。Ubuntu/Debian 服务端示例：

```bash
sudo apt install nfs-kernel-server
sudo mkdir -p /srv/nfs/lab
sudo chown nobody:nogroup /srv/nfs/lab
```

在 `/etc/exports` 中用实际实验网段限制客户端，例如：

```text
/srv/nfs/lab 192.168.56.0/24(rw,sync,root_squash,no_subtree_check)
```

应用并检查导出：

```bash
sudo exportfs -rav
sudo exportfs -v
sudo systemctl enable --now nfs-kernel-server
```

客户端安装 `nfs-common` 后验证：

```bash
sudo mkdir -p /mnt/nfs-lab
sudo mount -t nfs 服务器IP:/srv/nfs/lab /mnt/nfs-lab
mount | grep nfs-lab
touch /mnt/nfs-lab/client-test
sudo umount /mnt/nfs-lab
```

不要为了省事使用对所有主机开放的 `*`、`no_root_squash` 或过宽写权限。若写入失败，应核对导出范围、UID/GID、目录权限、防火墙和服务端日志，而不是直接把目录改成 `0777`。

#### 11.3.3 FTP：兼容性实验与更安全的替代方案（补充）

传统 FTP 的控制与数据连接会增加防火墙/NAT 配置复杂度，普通 FTP 还不加密用户名、密码和文件内容。能使用 SSH 时，优先选择 SFTP；只有兼容旧设备确有需要时才部署 FTP，并限制在隔离环境。

Ubuntu/Debian 的最小 vsftpd 实验流程：

```bash
sudo apt install vsftpd
sudo cp /etc/vsftpd.conf /etc/vsftpd.conf.bak
sudo systemctl enable --now vsftpd
systemctl status vsftpd --no-pager
ss -lntp | grep ':21'
```

修改配置前先查 `man 5 vsftpd.conf`。若只允许本地账户并允许写入，至少核对 `anonymous_enable=NO`、`local_enable=YES`、`write_enable=YES`，同时配置合理的目录权限、用户限制、被动端口范围和防火墙规则。修改后先检查日志，再重启并从客户端验证。不要照搬示例用户名、目录和匿名上传设置；公开匿名写入目录会带来恶意文件、空间耗尽和内容分发风险。

#### 11.3.4 通用验收清单（补充）

1. 包来自受信软件源，系统和服务已更新。
2. 配置文件有备份，语法检查通过。
3. 服务只监听预期地址和端口，防火墙仅允许必要来源。
4. 使用最小权限账户和目录，不在配置中写明文秘密。
5. 分别验证成功路径和失败路径，例如错误用户、越权目录、断网和服务停止。
6. 记录回滚方式、日志位置、开机启动状态和测试命令。
