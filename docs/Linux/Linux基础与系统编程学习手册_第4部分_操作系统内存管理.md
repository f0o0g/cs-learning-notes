## 第 1 章 操作系统内存管理基础

本章以 Windows/通用操作系统概念为背景，不把历史 32 位示例或教学模型直接当成现代 Linux、Windows 64 位实现细节。重点是理解地址空间、分配模型、分页、分段和段页式的基本关系。

### 1.1 计算机组成、内存与管理目标

经典冯·诺依曼模型常把计算机概括为运算器、控制器、存储器、输入设备和输出设备。现代 CPU 内含运算单元、控制逻辑、寄存器和缓存等；主存位于处理器与外部存储之间，为正在运行的代码和数据提供较低延迟的访问空间。程序未运行时通常保存在 SSD、硬盘等外部存储中，运行时由操作系统建立进程地址空间并按需把相关内容映射到内存。

```text
输入设备 ──> 主存 <──> CPU（控制与运算） ──> 主存 ──> 输出设备
                  ▲                         │
                  └──── 外部存储/映射文件 ──┘
```

主机、内存与 I/O 设备的关系如下图：

![计算机硬件结构：主机、内存与 I/O 设备](<assets/08_计算机硬件结构_4K.png>)

内存管理不只是“安全”两个字，至少承担以下职责：

- 为进程提供彼此隔离的虚拟地址空间，并允许显式共享指定区域。
- 记录哪些虚拟页已提交、驻留、换出、受保护或尚未映射。
- 在有限物理内存、页面文件和多个进程之间调度资源。
- 实现只读、可写、可执行等页面保护，并在非法访问时报告异常。
- 支持共享库、内存映射文件、写时复制和按需调页等机制。

> 纠错：C 指针越界属于未定义行为，不保证每次都立即触发访问异常；如果错误地址仍落在已映射且可访问的页中，程序可能静默破坏数据。内存保护以页面等硬件粒度工作，不理解 C 对象边界。内存泄漏是程序丢失对已分配资源的可用引用，操作系统隔离不能自动替程序发现或释放仍被视为占用的内存。

### 1.2 分配方式、地址与碎片

按教学模型，内存分配可先分成两大类：

```text
内存分配
├─ 连续分配
│  ├─ 单一连续分配
│  ├─ 固定分区分配
│  └─ 动态分区分配
└─ 非连续分配
   ├─ 页式
   ├─ 段式
   └─ 段页式
```


- 单一连续分配：内存中同时只装入一个用户作业，适合解释早期或资源受限的单任务模型，不代表现代家电必然采用该方案。
- 固定分区：启动前划定若干大小固定或不同的分区，作业选择能容纳自己的分区；分区内未利用部分形成内部碎片。
- 动态分区：按作业需求从空闲区切分连续区域；释放顺序不同会形成不相邻的空洞，即外部碎片。
- 非连续分配：一个进程的内容可放入多个不相邻物理区域，通过页表、段表或组合结构完成地址转换。

逻辑地址或虚拟地址是程序使用的地址表示；物理地址指主存中的实际位置。处理器中的地址转换硬件（通常称 MMU）依据操作系统维护的页表等结构完成转换，TLB 可缓存近期转换。不能把逻辑地址说成毫无对应空间的“假地址”，也不能把全部映射工作简单归给 CPU 中某一个普通软件函数。

碎片的稳定定义是：

- 内部碎片：已分配区域内部因分配粒度大于实际需求而未被利用的空间，例如最后一页未装满。
- 外部碎片：多个已分配区域之间形成的小空洞；总空闲量可能足够，但缺少满足连续大小要求的单个区域。

### 1.3 页式存储与地址转换

页式管理把进程虚拟地址空间切成固定大小的页，把物理内存切成同样大小的页框。页表记录“虚拟页号 → 物理页框号”的映射，因此相邻虚拟页可以位于不相邻物理页框。

```text
虚拟地址 = 页号 × 页大小 + 页内偏移
页号      = 虚拟地址 / 页大小
页内偏移  = 虚拟地址 % 页大小
物理地址  = 页表[页号] × 页大小 + 页内偏移
```

以下图的 4 KiB 页表为例，虚拟页 0、1、2、3 分别映射到物理页框 2、3、5、7。逻辑地址 4300 的计算过程是：

```text
页号     = 4300 / 4096 = 1
页内偏移 = 4300 % 4096 = 204
页表[1]  = 3
物理地址 = 3 × 4096 + 204 = 12492
```

![页表映射与逻辑地址转换](<assets/05_分页地址映射_4K.png>)

页大小由处理器体系结构和操作系统配置决定。x64 与 ARM64 Windows 的常见基础页大小为 4 KiB，也可能使用大页；“只能取 1 KiB、2 KiB、4 KiB”以及“内存容量为 4 的倍数是为了能被 4 KiB 整除”都不是可靠因果解释。

#### 分页练习一：逻辑地址 2500

题目：页大小为 1 KiB，虚拟页 2 映射到物理页框 8，求逻辑地址 2500 的物理地址。

```text
页号     = 2500 / 1024 = 2
页内偏移 = 2500 % 1024 = 452
物理地址 = 8 × 1024 + 452 = 8644
```


#### 分页练习二：逻辑地址 1024 与共享页

页大小为 1 KiB 时，进程 A 的逻辑地址 1024 位于虚拟页 1、页内偏移 0。示例中的 A 页表把虚拟页 1 映射到物理页框 3，因此变量位于页框 3，若题目要求字节物理地址则为 `3 × 1024 = 3072`。

若要求 A 的虚拟页 4 与 B 的虚拟页 5 共享物理页框 4，就应在两个页表相应表项中都填 4。共享的是同一物理页框，两个进程使用的虚拟页号不必相同，页面权限也可分别配置。


### 1.4 缺页与页面置换

页表项通常还包含有效/驻留、访问权限、脏页等状态。当线程访问的虚拟页没有驻留在物理内存时，处理器触发缺页异常，操作系统判断该访问是否合法：

1. 若地址未映射或权限不允许，向进程报告访问错误。
2. 若页面合法但未驻留，从映像文件、映射文件、页面文件或零页来源准备内容。
3. 若没有空闲页框，选择牺牲页；脏页可能需要写回。
4. 更新页表并恢复被中断的指令。

三种经典页面置换算法如下：

- OPT（最优）：替换未来最长时间不会被访问的页。它需要知道未来访问序列，主要用作理论最优基线，不能直接作为在线通用实现。
- FIFO（先进先出）：替换驻留时间最久的页；实现简单，但可能出现分配更多页框反而缺页更多的 Belady 异常。
- LRU（最近最少使用）：替换过去最长时间未访问的页；更符合局部性，但精确维护成本较高，实际系统常使用近似算法。


### 1.5 页式存储的优缺点

页式管理的主要优点是：物理分配不要求连续，消除按可变连续区分配产生的外部碎片；固定页框便于回收、共享和保护，并能结合按需调页提高物理内存利用率。

主要代价包括：

- 最后一页通常未装满，形成内部碎片。
- 页表、反向映射、工作集和置换状态需要内存与维护开销。
- 地址转换增加层次；TLB 未命中或缺页时延迟显著增加。
- 基本分页模型可以要求整个作业装入，但现代虚拟内存通常通过按需分页只让工作集驻留，不能把“程序必须全部装入内存”当作 Windows 分页的固定缺点。
- 分页扩大可用虚拟地址空间不等于凭空增加内存；提交限制、页面文件、物理内存和工作集压力仍会约束程序。


### 1.6 段式存储

段式管理按程序的逻辑单位划分可变长段，例如主程序、子程序、只读代码、数据和栈。每个段可从偏移 0 开始编址，逻辑地址写成 `(段号, 段内偏移)`。段表至少提供基址、段长（界限）和保护状态：

```text
若 0 <= 段内偏移 < 段长：物理地址 = 基址 + 段内偏移
否则：地址越界
```

下图中的示例段表为：

| 段号 | 段长 | 基址 | 有效物理范围 |
|---:|---:|---:|---:|
| 0 | 30 KiB | 40 KiB | `[40, 70)` KiB |
| 1 | 20 KiB | 80 KiB | `[80, 100)` KiB |
| 2 | 15 KiB | 120 KiB | `[120, 135)` KiB |
| 3 | 10 KiB | 150 KiB | `[150, 160)` KiB |

![段号、段长、基址与物理内存映射](<assets/06_分段地址映射_4K.png>)

段的核心特征是逻辑意义完整、长度可不同、段间地址不连续。代码、数据、栈和独立子程序只是常见例子，不代表每个编译器或现代 Windows 都用经典纯分段方案直接分配物理内存。


段式管理便于按逻辑单位独立保护、共享和修改，理想模型中没有固定页粒度造成的内部碎片；但可变长段需要连续物理区域，会产生外部碎片，可能需要紧缩或更复杂的空闲区管理。不能因为单个段较小就断言外部碎片一定很小。


#### 分段越界练习

示例段表为：

| 段号 | 基址 | 段长 |
|---:|---:|---:|
| 0 | 1100 | 800 |
| 1 | 3310 | 50 |
| 2 | 5000 | 200 |
| 3 | 4100 | 580 |
| 4 | 2000 | 100 |

- `(0, 790)` 有效，物理地址为 1890。
- `(2, 88)` 有效，物理地址为 5088。
- `(1, 30)` 有效，物理地址为 3340。
- `(3, 290)` 有效，物理地址为 4390。
- `(0, 810)` 越过段 0 的 800 界限。
- `(4, 98)` 有效，物理地址为 2098。
- `(4, 120)` 越过段 4 的 100 界限。

因此题目中不能转换的组合是 `(0, 810)` 与 `(4, 120)`，原因是逻辑地址转换时段内偏移越界。


### 1.7 段页式存储与三种模型比较

段页式先按逻辑意义分段，再把每个段切成固定大小的页。逻辑地址可表示为：

```text
(段号, 段内页号, 页内偏移)
```

先分段、再分页的地址空间与逻辑地址的三个字段如下图：

![段页式作业地址空间与三元逻辑地址](<assets/04_段页式地址空间_4K.png>)

段表项指出该段的页表位置、长度和保护信息；段内页表再把虚拟页映射到物理页框。地址转换先检查段和页的范围，再查页表并组合页框号与页内偏移。


```text
段表
  ├─ 段 0 -> 页表 0 -> 页框 ...
  ├─ 段 1 -> 页表 1 -> 页框 ...
  └─ 段 n -> 页表 n -> 页框 ...
```

图中的“状态、页表大小、页表始址”和页表中的“页号、状态、存储块号”表达了两级查找关系；未驻留状态仍需通过操作系统缺页处理，而不是直接得到物理页框。

![段表、段内页表与物理页框的地址转换](<assets/07_段页式地址转换_4K.png>)

段页式保留按段保护、共享和组织的优点，又通过分页避免要求每段占据连续物理区域。它增加段表、多个页表和转换管理开销。经典“物理页框分配”模型主要仍有各段末页的内部碎片，不应机械写成必然同时产生物理内存的内部、外部碎片；具体开销还取决于表和其他元数据如何分配。


三种模型可这样比较：

| 对比项 | 页式 | 段式 | 段页式 |
|---|---|---|---|
| 划分依据 | 固定大小 | 逻辑意义、可变长度 | 先逻辑分段，再固定分页 |
| 逻辑地址教学表示 | 页号、页内偏移 | 段号、段内偏移 | 段号、段内页号、页内偏移 |
| 物理连续要求 | 不要求 | 每段通常要求连续 | 不要求整段连续 |
| 典型碎片 | 内部碎片 | 外部碎片 | 主要是末页内部碎片 |
| 共享和保护 | 可按页 | 可按逻辑段 | 可按段组织、按页映射 |
| 表结构 | 页表 | 段表 | 段表加段内页表 |


“页式地址一维、段式地址二维”是教学表示，不意味着机器中的虚拟地址不是一个比特序列；段号、页号和偏移最终都编码在地址或相关上下文中。无 TLB 的最简模型常把一次页式/段式访问描述为“查表一次、访问数据一次”，段页式描述为“查段表、查页表、访问数据”；真实系统存在多级页表、TLB、缓存、缺页和硬件并行，访问次数不是固定常量。

> 纠错：段页式并非“只在大型计算机使用、个人 PC 不使用”的通用结论。x86 历史上支持分段与分页组合；现代 64 位 Windows 主要采用分页虚拟内存并使用近似平坦的段配置。应区分教学上的段页式模型、处理器提供的机制和具体操作系统策略。
