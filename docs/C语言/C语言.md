# C 语言

> 本文档把前言与文章索引合在一处：前半部分说明这套文档是什么、怎么读，后半部分按章、按主题定位正文。

## 前言

本套文档面向正在建立 C 语言完整知识体系的学习者：从程序结构、类型和控制流出发，逐步进入指针、数组、函数、字符串、结构体、文件与组件化开发。每一章都要求能落到“可编译、可运行、可解释”的程度，不停留在语法罗列。

### 这套文档覆盖什么

全书共 12 章，按“语言基础 → 内存模型 → 工程能力”三段推进：

1. **语言基础（第 1～2 章）**：程序怎样编译运行，顺序、选择、循环怎样表达算法；数据怎样编码、转换并参与表达式计算。
2. **内存模型（第 3～9 章）**：地址与指针、一维与多维数组、函数调用与栈帧、字符串的 `'\0'` 模型、结构体对齐与链表。
3. **工程能力（第 10～12 章）**：文件持久化、多文件工程与库、命令行参数与 Visual Studio 调试闭环。

第 7 章同时承担“编译期机制”的主线：函数指针、`typedef`、枚举、`const`、宏、链接与程序内存区域在这里统一收口。

### 每章怎么组织

重要知识点尽量按下列顺序展开，短小知识点会合并相邻步骤，避免机械重复：

> 概念与用途 → 语法模板 → 参数与返回值 → 底层模型 → 示例 → 输出与解析 → 易错点与练习

具体约定：

- 函数接口说明区分输入、输出、输入/输出、长度、容量、可空性和所有权。没有明确转移所有权时，指针参数默认只是调用期间的借用。
- 第 1～10 章及第 12 章末尾设有“综合题库（含答案与解析）”；第 11 章是纯工程章节，以组件接口与工程约定为主，不设统一题库。
- 作业原版与批注版的实质重复题只保留一次；条件不同、代码不同或小问不同的题目仍分别保留。
- 题库答案以标准 C 为准。若原题含未定义行为、约束违反、实现定义或平台依赖，先给标准结论，再说明 x86、x64 或 MSVC 中可能观察到的常见结果。

### 三条学习路线

- **第一次学习**：按 1～12 章顺序阅读。每个示例先遮住输出手工推导，再运行验证；遇到指针、递归、矩阵或链表时，画出变量、地址和连接关系。
- **算法强化**：重点第 1、4、5、6 章，依次练习枚举与计数、查找与排序、矩阵变换、最大公约数与汉诺塔，并为高风险算法手工制作变量跟踪表。
- **工程强化**：重点第 6～12 章，先完成单函数测试，再拆分接口与实现，随后练习结构体、动态内存、链表、文件、静态库与动态库、第三方 C 接口，最后补齐命令行入口与 IDE 调试。

### 阅读与运行约定

- 建议使用支持 C11 的编译器，并打开较严格警告；若使用编译器专有安全函数或扩展语法，应同时理解其可移植替代方案。
- 代码围栏标为 `c` 或 `cpp`。`cpp` 表示示例按 C++ 编译单元组织，核心知识仍围绕 C 风格接口与内存模型。
- `text` 围栏给出精确输出、示例输入输出、代表性结果、错误诊断或可观察效果。
- 地址、随机数、类型宽度、结构体布局、浮点末位和系统错误文本可能因平台而变化，文中会明确适用条件。
- 未定义行为没有可信的固定输出；相应示例会解释风险，并给出可验证修正版。
- 除特别说明外，数组下标从 `0` 开始，区间优先采用半开形式 \([begin, end)\)。
- 建议第一次阅读时先遮住“答案”和“解析”手算；代码输出题先写变量跟踪表或内存字节图，再编译验证。

单文件编译示例：

```text
cc -std=c11 -Wall -Wextra -Wpedantic program.c -o program
```

含数学函数时，部分 Unix 工具链需在末尾链接数学库：

```text
cc -std=c11 -Wall -Wextra -Wpedantic program.c -lm -o program
```

### 练习方法

对每个程序执行四步：

1. 写出输入、期望输出和边界条件。
2. 手工推导关键变量，特别是循环边界、指针位置和容器长度。
3. 编译运行，先处理警告，再比较输出。
4. 主动加入空输入、单元素、最大值、重复值、失败路径等测试。

调试时不要只盯着最终输出。断点、单步、调用栈、局部变量、内存窗口和监视表达式分别回答“执行到哪里”“谁调用了谁”“值怎样变化”“字节怎样排列”。
